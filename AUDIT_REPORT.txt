PVZ CONTROL 1.4 — проверка 06.11.2026

ИСПРАВЛЕНО
- Кнопки календаря показывали буквальные фрагменты JS вместо текста и атрибутов.
- Дата первого платежа рассрочки переведена на календарь выбора даты.
- Сохранение из устаревшей вкладки блокируется для commit/undo/redo/import.
- Повреждённое исходное хранилище не заменяется пустой базой.
- Добавлен экспорт исходного хранилища и доступ к контрольным копиям.
- Обработчики visualViewport снимаются при смене/закрытии формы.
- Закрытие формы закрывает календарь выбора даты.
- Импорт проверяет безопасный формат ID, ставки и сохранённые ставки смен.
- Восстановление старых копий дополняет отсутствующие массивы новых разделов.
- Экранированы цвета при формировании HTML.
- Сохраняются выбранный ПВЗ, фильтр сети и строка поиска настроек.
- Исправлен заголовок финансов; поиск настроек повторно применяется при рендере.
- Добавлены мобильные ограничения ширины, safe area и размер шрифта полей 16px.
- Telegram SDK загружается асинхронно; подписанные данные читаются также из hash.

ПОДГОТОВЛЕНО
- Изолированные пользовательские базы, Telegram HMAC-проверка на сервере.
- Раздельное локальное хранение подтверждённых Telegram-аккаунтов.
- Копирование прежней локальной базы только с явным выбором пользователя.
- Сохранение офлайн, таймаут запросов, повтор при возвращении интернета.
- Атомарная проверка версии на сервере и остановка при конфликте.
- Выбор версии при конфликте с контрольной копией перед заменой.
- SQL с RLS, запретом доступа anon/authenticated и RPC только для service_role.
- До 30 предыдущих серверных версий; скачивание для обычного JSON-восстановления.

ПРОВЕРЕНО АВТОМАТИЧЕСКИ
- 17 проверок ядра и подписи Telegram: tests/core.cjs.
- 8 сценариев синхронизации с имитацией API: tests/sync.cjs.
- Сценарии форм: ПВЗ, сотрудник, смена, факт, выплата, проблема, заметка, отзыв.
- Рассрочка 1000/3 = 333.34 + 333.33 + 333.33; январь 31 -> февраль 28.
- Погашения, границы настроек, график 2/2, сохранение и перезагрузка.
- JSON backup/restore, CSV с защитой формул, создание XLSX, HTML печати.
- XLSX прочитан openpyxl: лист «Смены», 18 строк, 7 столбцов.

ОГРАНИЧЕНИЯ
- Развёртывание БД и функции заблокировано автоматической проверкой действий
  в действующем Supabase-проекте игры. Повторная попытка после проверки отсутствия
  конфликтующих объектов завершилась истечением подтверждения. Изменения БД не
  подтверждены как применённые; серверная синхронизация НЕ работает в production.
- Нужны согласование использования этого проекта и секрет PVZ_CONTROL_BOT_TOKEN.
- Реальные два устройства, Telegram и iPhone не проверены.
- Локальный Chromium отсутствует, загрузка браузера не завершилась корректно.
- PDF формируется через печать; нативное скачивание iOS не подтверждено.
- Одновременные независимые изменения требуют выбора базы; слияния по полям нет.
- Запуск офлайн после полного закрытия браузера не гарантируется (нет service worker).
- Общий доступ разным Telegram-пользователям к одной базе не реализован.
- Полный релиз требует проверки настоящей серверной синхронизации после подключения.
