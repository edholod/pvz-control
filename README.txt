PVZ CONTROL by @edholod — 1.4, кандидат для проверки

Приложение: https://edholod.github.io/pvz-control/
Статические файлы: index.html, app.js, sync.js.

Серверный исходный код подготовлен, но сервер не развёрнут и реальная
синхронизация пока НЕ подключена. Не объявлять эту версию облачным релизом.

Сервер: server/schema.sql, server/index.ts, server/auth.mjs, server/validate.mjs.
Целевой проект: duerixyhzapotoeclggz (wb-pvz-tycoon).
Существующие таблицы и функции игры не изменяются.
1. Применить server/schema.sql после подтверждения размещения в этом проекте.
2. Развернуть отдельную функцию pvz-control с verify_jwt=false.
   Она сама проверяет initData по HMAC SHA256, подпись, auth_date и Telegram ID.
   Передать все 3 файла обработчика, включая auth.mjs и validate.mjs.
3. В Supabase Edge Function Secrets задать PVZ_CONTROL_BOT_TOKEN:
   токен именно бота @edholod_wbbot. Не помещать его в репозиторий, клиент или чат.
4. Проверить запуск из реальной WebApp-кнопки этого бота и обмен между устройствами.

При открытии обычной ссылки приложение работает локально.
Telegram initDataUnsafe не используется для предоставления доступа.
Сервер принимает только подписанные запросы не старше 24 часов.
После истечения срока нужно заново открыть Mini App из бота.

База принадлежит одному Telegram-пользователю. Общий доступ нескольких разных
пользователей к одной сети ПВЗ не реализован. Это отдельная модель приглашений.
Синхронизация: при сохранении, открытии экрана, возврате сети и каждые 30 секунд
на активной странице. Изменения при недоступном сервере остаются локально.
Конфликты: атомарная проверка номера серверной версии; ручной выбор базы.
Автоматического объединения конфликтующих баз нет.

Миграция: прежний ключ pvz-control-v1 остаётся целым. После подтверждённого
входа предлагается перенести его копию в pvz-control-tg-<Telegram ID>.
На сервере хранится актуальная база и до 30 предыдущих версий на пользователя.
Локально сохраняются 3 контрольные копии перед заменой серверными данными.
Резервные JSON-копии можно скачивать и восстанавливать.
Серверные архивы в той же БД не заменяют независимую резервную копию.

PDF: печать в отдельном окне; сохранение PDF зависит от платформы.
Уведомления показываются внутри приложения. Рассылки через бота не добавлялись.

Проверки (Node.js 22+):
node --check app.js
node --check sync.js
node tests/core.cjs
node tests/sync.cjs
node tests/flows.cjs
Тесты синхронизации используют имитацию API; это не проверка рабочего сервера.
